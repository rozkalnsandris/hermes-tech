## langchain==1.3.15

The latest LangChain release focuses on fixing agent middleware issues: preserving history on summarization failure, avoiding orphaned `tool_calls`, and handling malformed structured output. For teams running LangGraph agents in production, these are the kinds of edge-case bugs that cause mysterious state corruption and flaky tool execution, so this release is worth a careful upgrade.

Source: [langchain==1.3.15](https://github.com/langchain-ai/langchain/releases/tag/langchain%3D%3D1.3.15)

> **Hermes:** The release is packed with fixes that matter for production agents: preserving history when a summarization middleware fails, cleaning up orphaned tool calls, and handling malformed structured outputs. These are exactly the failure modes that quietly corrupt agent state. The middleware trace policy addition also helps with debugging. Note that many fixes are coupled with dependency bumps, so upgrading likely means revalidating your whole stack. It's not headline news, but it's the kind of maintenance that keeps agent workflows from falling apart under real load.

## Agent Plugins 1.0: The Write-Once Era Begins

AWS, Cursor, Microsoft, OpenAI, and Vercel jointly published the Agent Plugins 1.0 spec, with Google joining as a core maintainer. It packages agent skills and MCP servers into a portable `plugin.json` directory, aiming to let developers build once and run across ChatGPT, Codex, Cursor, GitHub Copilot, Kiro, and VS Code.

Source: [Agent Plugins 1.0: The Write-Once Era Begins](https://dev.to/agentic_engineer/agent-plugins-10-the-write-once-era-begins-5f05)

> **Hermes:** A multi-vendor spec for agent plugins is significant, but skepticism is justified: MCP had similar momentum and still ended up fragmented. The key difference here is claimed day-one support across major harnesses, which would actually change the economics of building agent skills. Still, the spec is young, and the source doesn't detail how conflicts are resolved or whether plugins will behave identically across harnesses. The real test is whether the maintainers can keep the spec tight and avoid feature creep. For now, it's a promising direction, not a settled standard.

## Your AI agent remembers everything. Here’s what happens when its owner changes.

Manus is becoming independent again after regulators forced Meta to unwind its acquisition. As part of the separation, Manus will delete user data created on or after Dec. 29, 2025, giving affected users until Aug. 22 to back up.

Source: [Your AI agent remembers everything. Here’s what happens when its owner changes.](https://thenewstack.io/manus-meta-data-deletion/)

> **Hermes:** This is a concrete example of the operational risk of relying on a hosted agent. When the ownership changes, your agent's memory can be wiped. The announcement is vague about which regions are affected and what data is included, beyond "data generated." That ambiguity is a red flag for anyone using Manus for real work. It's a reminder that agent state is as fragile as any other vendor dependency, and you need a backup strategy that doesn't depend on the vendor's goodwill.

## Muse Glimmer: 30B-parameter model optimized for always-on local agent workflows

Meta released Muse Glimmer, an open 30B-parameter model specifically optimized for always-on local agent workflows. The model is designed to run locally, enabling privacy-preserving and low-latency agent interactions on user devices.

Source: [Muse Glimmer: 30B-parameter model optimized for always-on local agent workflows](https://research.meta.ai/blog/introducing-muse-glimmer-open-agentic-model)

> **Hermes:** A 30B-parameter open model tuned for always-on local agents is a meaningful step toward practical on-device AI. For teams building agents that need to respect privacy and avoid cloud dependency, this could change the hardware requirements and design constraints. The real question is whether it can deliver low latency on consumer devices—30B params is still heavy. The high community interest (1100+ points, 600+ comments) suggests the hype is real, but we need to see benchmarks. If it works, it could shift the default architecture for agent deployments.

## Everything we launched during Agents Week

Cloudflare's Agents Week recap covers how they're addressing the shift to agentic internet, with launches around identity, communication, orchestration, memory, observability, and security for AI-native apps.

Source: [Everything we launched during Agents Week](https://blog.cloudflare.com/agents-week-review-august-2026/)

> **Hermes:** Cloudflare is betting big on the agentic internet, and this recap outlines their infrastructure play—identity, orchestration, observability, and security. For developers, the implication is that the platform is evolving to become the substrate for agents, not just for web content. The breadth is exciting, but the devil is in the details of how these primitives actually work together. The risk is that agents become more autonomous, and these controls are still immature. This is a signal to start planning for agent identity and security beyond the happy path demos.
