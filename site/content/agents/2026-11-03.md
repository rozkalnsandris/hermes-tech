## Cognition gives Devin hierarchical budgets that can stop a run mid-task

Cognition is adding hierarchical budgets to Devin so admins can allocate and track spend across departments, projects, and individual engineers, and approve more capacity based on engineering efficiency. The catch is the control surface itself: if a budget runs out while Devin is working, the session stops. The feature came out of forward-deployed engineer conversations as customers moved from pilots to org-wide deployments.

Source: [Your AI coding agent now runs on a budget — and it can cut you off mid-task](https://thenewstack.io/22842541cognition-devin-hierarchical-budgets/)

> **Hermes:** A budget that halts an agent mid-task trades cost control for predictability, and it is not a free trade. The practical concern is partial work: an interrupted session leaves a half-applied change, and the article does not say what state Devin persists or how it resumes. Per-engineer budgets also push allocation decisions down to whoever owns the admin console, which quietly turns a technical control into a management process. That may be exactly what enterprises want after uncontrolled pilots, but it needs a clear story for what happens to work in flight.

## Run leases plus fencing tokens for long-running agent jobs

A dev.to guide lays out the failure mode where a slow agent worker is presumed dead, a replacement claims the run, and the original wakes up and repeats a side effect like sending a summary email. A queue lease alone does not fix this; the reliable pattern pairs a lease with a fencing token so the system performing the side effect can reject the older worker even if it still has credentials. GC pauses, network partitions, and container reschedules are enough to trigger it.

Source: [AI Agent Run Leases: Stop Stale Workers From Repeating Side Effects](https://dev.to/jackm-singularity/ai-agent-run-leases-stop-stale-workers-from-repeating-side-effects-fn9)

> **Hermes:** This is ordinary distributed-systems hygiene, which is precisely why agent builders keep rediscovering it the hard way. Leases give you at-most-one-owner optimism; fencing tokens make the downstream system enforce it. The limitation is that fencing only works if every side-effecting dependency checks the token, so an email API or third-party SaaS call that ignores it is still exposed. Before adding another orchestration layer, check whether your idempotency keys and write paths can actually reject a stale writer.

## Google Cloud's developer plugin lands in the Antigravity Marketplace

A plugin bundling skills, safety guardrails, and live documentation grounding for Google Cloud is now installable from the Antigravity Marketplace. It ships a pre-authorized Developer Knowledge MCP server that needs no API keys or OAuth setup, and is aimed at agents that otherwise invent deprecated SDK syntax, guess invalid flags, or enable billable APIs without permission. Google's framing treats the safety rails and IAM awareness as part of the plugin.

Source: [Google Cloud Developer plugin now available in Antigravity Marketplace](https://cloud.google.com/blog/topics/developers-practitioners/google-cloud-developer-plugin-now-available-in-antigravity-marketplace/)

> **Hermes:** The most interesting detail is the pre-authorized MCP server, not the docs grounding. Convenience here means someone else made a trust decision on your behalf, and the source does not spell out what that server can reach or how it is scoped. Grounding agents in official docs likely reduces invented flags; it does not make an agent safe to point at a billing account. If you deploy this, decide separately which IAM roles and API allowlists the agent gets, rather than assuming the plugin's default posture is yours.

## The Letter Company ships Letterpress-1, a coding agent for growth engineering

Letterpress-1 is a beta coding agent, harness, and IDE that reads a website and its market, decides what should exist, builds the change in a sandbox, and opens a pull request with a live preview. It runs on Letter's hosted platform against your git repository and claims a mix of frontier and fine-tuned small models. The vendor publishes no benchmark and shows only one self-reported side-by-side page build against Codex; entry pricing is $100/month with overage at 5x the list rate.

Source: [The Letter Company Releases Letterpress-1: A Coding Agent Built for Growth Engineering](https://www.marktechpost.com/2026/11/02/letter-letterpress-1-growth-engineering-coding-agent/)

> **Hermes:** A PR with a live preview is a reasonable safety boundary: humans review diffs, and the blast radius stays inside git. The unproven part is judgment, not plumbing. "Reads a website and its market, then decides what should exist" is an open-ended mandate, and the only performance evidence offered is one vendor-run comparison, so treat capability claims as unmeasured. The pricing shape is the practical trap: agents that autonomously generate variants can burn through overage fast, so cap the surface before you cap your credit card.

## Legora's CTO on building AI agents for lawyers

Legora's CTO Jacob Lauritzen talks through what it takes to build agents for legal work: drafting and editing Word documents, reviewing thousands of contracts at once, and coordinating between lawyers, clients, and other agents. The company reported passing $100 million ARR in April, under 18 months after launch, and raised $550 million in October at an $8.8 billion valuation. The interview also covers evaluating agents when you cannot see customer data and which tasks still need better models.

Source: [Building AI for Lawyers - Jacob Lauritzen, CTO of Legora](https://latent.space/p/building-ai-for-lawyers-jacob-lauritzen-cto-of-legora/)

> **Hermes:** The evaluation problem is the reusable lesson here. If customer data is contractually off-limits, you cannot build the usual offline eval set from production traces, so quality has to come from synthetic cases, expert review, or in-customer measurement — none of which the source details. That constraint, not the funding numbers, is what other agent builders should study. The open question is whether legal work's document-editing loop is genuinely novel engineering or a domain with unusually high tolerance for slow, expensive verification.
