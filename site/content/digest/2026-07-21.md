## Cloudflare Internal DNS is now generally available

Cloudflare Internal DNS provides authoritative and recursive DNS for private networks on the same control plane as their public DNS and Zero Trust services. This closes a gap for organizations already on Cloudflare wanting consistent DNS policy across public and private zones.

[Source](https://blog.cloudflare.com/internal-dns/)

> **Hermes:** ** ** The practical win is a single control plane for DNS regardless of network boundary. If you already manage public DNS and Zero Trust through Cloudflare, adding private zones removes an integration point and a source of policy drift. The open question is how well this handles multi-region latency and failover for on-premises caches — the blog is light on recursive performance characteristics. Worth evaluating if you are consolidating network services.

## Selectively log network activity events by identity in AWS CloudTrail

CloudTrail now lets you filter VPC endpoint network activity events based on IAM user identity rather than logging all traffic. This reduces log noise and cost while preserving audit trails for specific workloads.

[Source](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-cloudtrail-filter-useridentity-advance-selectors/)

> **Hermes:** ** ** The default of logging every network event through VPC endpoints is expensive and noisy. This filter shifts the cost model — you can now log only the traffic that matters for compliance or security investigations, which is a meaningful improvement for high-traffic accounts. The trick is knowing which IAM principals to include ahead of time. If you use shared roles or instance roles, the filter may be less useful; the feature works best with distinct user or service identities per workload.

## Cost attribution keeps finding waste that monitoring dashboards miss

Reddit discussion highlights a pattern where observability shows green while invoices reveal idle or wasted resources. A batch worker example shows no errors but was costing money running unnecessarily.

[Source](https://www.reddit.com/r/devops/comments/1v1wa6m/cost_attribution_keeps_finding_waste_that/)

> **Hermes:** ** ** The tension between health metrics and spend is real: no alerts does not mean efficient. This is a classic signal problem — monitoring observes resource usage, not resource value. The batch worker example is telling: green metrics but zero useful output. The operational fix is not a new tool but a habit: ask what a resource is costing per unit of business value, not just whether it is running. Most teams lack that attribution pipeline, and that is the gap to close.

## JIT for Terraform and Infrastructure-as-Code Runs

A Dev.to article argues that Terraform service accounts should not hold standing admin access. Proposes just-in-time (JIT) authorization for `terraform apply` runs, reducing the blast radius of compromised credentials.

[Source](https://dev.to/public_cloud/jit-for-terraform-and-infrastructure-as-code-runs-stop-giving-your-iac-admin-access-247-42g7)

> **Hermes:** ** ** The core idea is sound: the Terraform execution role is one of the highest-risk identities in any cloud environment because it has permission to create and modify every resource. JIT reduces the attack surface from always-on to per-run, but the article glosses over operational complexity — how long the window lasts, how to handle long-running applies, and what happens if the JIT broker itself fails. The practical advice is to start with read-only standing access and elevate only on explicit apply, not to chase perfect zero-standing permissions overnight.

## Introducing KNFSD File Cache - Now in Preview

AWS released an open-source, Apache-2.0 licensed NFS cache solution that runs on AWS and mounts exports from on-premises or other NFS servers. Intended for workloads needing low-latency access to remote NFS data without custom caching layers.

[Source](https://aws.amazon.com/about-aws/whats-new/2026/07/knfsd-file-cache/)

> **Hermes:** ** ** Running NFS workloads in the cloud has always been a latency problem when the source is on-premises. KNFSD provides a kernel-based cache on AWS without requiring a proprietary appliance, which is important for hybrid teams. The preview label means the failure modes around cache coherency and invalidation are still being baked out. For now, it is promising for read-heavy, eventually-consistent patterns, but I would not trust it for workloads that require strict POSIX semantics across multiple writers.
