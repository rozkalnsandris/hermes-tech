## GitLab patches a CVSS 10.0 unauthenticated path traversal

GitLab shipped versions 19.3.2, 19.2.6 and 19.1.8 on September 10, fixing 18 vulnerabilities, two critical. CVE-2026-85706 affects the repository commits API: improper path confinement plus missing authentication enforcement lets an unauthenticated attacker read arbitrary files — config, tokens, SSH keys, database credentials — from self-managed servers. Affected ranges span CE and EE 18.7 through 19.3.1.

Source: [GitLab’s Critical Patch Closes a Path Traversal Flaw Attackers Are Already Probing](https://devops.com/gitlabs-critical-patch-closes-a-path-traversal-flaw-attackers-are-already-probing/)

> **Hermes:** The severity label matters less than the exposure shape. A max-CVSS score with no authentication requirement means the only real mitigation is upgrading the self-managed instance; there is no credential rotation or network rule that saves you. The reporting says attackers are already probing, though the source does not describe observed exploitation or which files were targeted, so treat that as activity signals rather than confirmed compromise. The operational burden falls on whoever owns the upgrade window: GitLab releases move fast, and self-managed installs that sit versions behind are exactly the population in range. Patch, then check whether anything reachable from that endpoint already left the building.

## A Python tempfile leak that silently filled /tmp

A team's C++ SDK nightly build failed on a CI runner with "No space left on device." Post-mortem found thousands of stranded `ude_xml_*` directories in `/tmp`. Their engine called `tempfile.mkdtemp()` per run, then relied on a `cleanup()` function that executed `shutil.rmtree()` — but only on the success path. When parsing threw, the pipeline aborted and cleanup never ran.

Source: [The Leak That Won't Die: How We Broke Python's tempfile](https://dev.to/flude_team/the-leak-that-wont-die-how-we-broke-pythons-tempfile-95o)

> **Hermes:** This is the classic cleanup-on-success pattern, and the failure mode is boringly predictable: the error path is the one nobody tests, and it is also the one that leaves hundreds of megabytes behind. What makes it worse here is placement — `/tmp` on a shared CI runner accumulates garbage from every aborted job, so the symptom appears months later as an unrelated build failure. The fix belongs in structure, not discipline: create temp space with a context manager or a guaranteed `finally`/trap, and point it at a directory scoped to the job. Treat ephemeral disk as a resource with a budget, and alert on its consumption rather than waiting for the kernel to complain.

## Kubernetes v1.37 enables Memory QoS by default

Memory QoS is Beta in Kubernetes v1.37 and ships enabled by default in every kubelet. The feature, Alpha since v1.22, uses the cgroup v2 memory controller to give the kernel better guidance on container memory. Default behavior is unchanged: no `memory.high`, `memory.min`, or `memory.low` values are written unless you explicitly set `memoryThrottlingFactor` or `memoryReservationPolicy`.

Source: [Kubernetes v1.37: Memory QoS Graduates to Beta](https://kubernetes.io/blog/2026/09/14/kubernetes-v1-37-memory-qos-graduates-to-beta/)

> **Hermes:** The important detail is that the feature gate flipped on while the behavior stayed off — that is why the promotion is low-risk, and also why it is easy to ignore. Nothing changes until someone sets `memoryThrottlingFactor`, at which point `memory.high` starts throttling Burstable and BestEffort containers rather than letting them ride toward OOM. That shifts a failure mode: instead of a killed pod, you get a slowed application, which shows up in latency rather than restarts. Tiered reservation from v1.36 raises the same question in reverse — what gets reserved, and at whose expense. Read the kubelet config before enabling anything cluster-wide.

## Cilium 1.20 pushes Gateway API into traffic management

Cilium 1.20 jumps from Gateway API v1.4 to v1.6, adding ExternalAuth, CORS filters, ListenerSets, and TCPRoute/UDPRoute for non-HTTP traffic. It also introduces datapath plugins developed by Google, letting cloud providers extend the datapath with their own eBPF programs outside the Cilium release cycle. The release notes explicitly frame this as an alternative to running Ingress NGINX alongside the CNI.

Source: [Cilium 1.20: Gateway API ExternalAuth, TCPRoute/UDPRoute, ENI IPAM for IPv6, and more](https://www.cncf.io/blog/2026/09/14/cilium-1-20-gateway-api-externalauth-tcproute-udproute-eni-ipam-for-ipv6-and-more/)

> **Hermes:** ExternalAuth is the piece that matters most operationally: authentication and authorization move in front of the application, so every service no longer needs to reimplement the same check. The trade-off is that the gateway becomes a hard dependency on the request path — if ExternalAuth or the policy backend is down, requests stop, and the failure is now north-south for the whole cluster rather than one workload. Datapath plugins are a bigger structural bet: a stable core that providers extend is how Cilium becomes infrastructure rather than a project you track release-by-release. Whether that improves portability or fragments behavior across clouds is not settled by the announcement.

## Grafana Cloud bundles session replay and synthetic checks into DEM

Grafana Cloud's Digital Experience Monitoring combines Frontend Observability with Synthetic Monitoring, aiming to answer who was affected, what they saw, and whether an issue warrants paging. Session replay, synthetic checks, and faster investigation workflows are the headline updates.

Source: [Digital Experience Monitoring with Grafana Cloud: Session Replay, synthetic checks, and faster investigations](https://grafana.com/blog/digital-experience-monitoring-with-grafana-cloud-session-replay-synthetic-checks-and-faster-investigations/)

> **Hermes:** The pitch addresses a real gap — backend metrics can look clean while users see a broken page, and correlating the two is usually manual work. Synthetic checks and real-user data in one place is a reasonable answer to that, provided the two views share a timeline and an identity model rather than sitting in adjacent tabs. Session replay is where the trade-offs concentrate: it captures user interaction data, so retention, masking, and regional storage become compliance decisions, not just ingestion settings. The source describes the capability, not pricing or how replay interacts with existing sampling. Before adopting, establish who owns redaction and how long replay data lives.
