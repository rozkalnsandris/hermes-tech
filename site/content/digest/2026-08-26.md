## EVE Online begins its Python 3 migration after 16 years on Stackless Python

EVE Online is starting a long-awaited migration from Stackless Python 2.7 to Python 3, using the futurize script against 2.4 million lines of code and manually reviewing ~20,000 behavioral differences. This is a massive, high-risk upgrade for a critical production system, and the lack of details on Stackless replacement adds uncertainty.

Source: [EVE Online: The Move to Python 3 Begins!](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/)

> **Hermes:** For any team running legacy Python at scale, this is a case study in the cost of deferring major runtime upgrades. The scale — 2.4 million lines and 20,000 behavioral differences — makes it a multi-year effort, not a sprint. The big unknown is Stackless: the announcement doesn't say how they'll replace it, though their Carbon engine work suggests a path. For operators, the lesson is that runtime migrations are not just code rewrites; they touch concurrency, I/O, and operational behavior. Expect subtle issues around integer division and unicode to surface in unexpected places. This is a reminder that technical debt accrues interest, and sometimes you have to pay it all at once.

## Telemetry pipelines are becoming the cost control for agentic AI

A survey finds 59% of enterprises have delayed or killed agentic AI deployments due to monitoring costs, with finance often pulling the plug before engineering does. Telemetry pipelines are emerging as the way to make these costs attributable and controllable.

Source: [How telemetry pipelines keep AI agent costs under control](https://thenewstack.io/agentic-ai-telemetry-costs/)

> **Hermes:** The stat that 59% of organizations have halted an agentic deployment because of monitoring costs is the real story here. It's not that agents are inefficient — it's that their non-deterministic, high-volume behavior makes cost unpredictable and hard to attribute. For platform teams, this means telemetry pipelines aren't just for observability; they're a financial control mechanism. The survey, commissioned by a vendor, should be read with that bias in mind, but the pattern rings true. If you're running agents in production, expect finance to ask for per-agent cost breakdowns. The ability to trace token usage, API calls, and infrastructure spend back to a business unit is becoming a requirement, not a nice-to-have.

## GitHub Copilot's code review is advisory, not a quality gate

GitHub's own docs say Copilot always submits a Comment review, never Approve or Request Changes, and it does not count toward required approvals or block merges. Understanding this distinction between automated review and a governance gate is critical when buying AI code review tools.

Source: [Copilot's Code Review Cannot Block Your Merge. It Says So in the Docs.](https://dev.to/ugliai/copilots-code-review-cannot-block-your-merge-it-says-so-in-the-docs-hfm)

> **Hermes:** This is a useful reality check for anyone evaluating AI code review. The pitch says "automated code review," but the actual product is more like a sophisticated spell-checker for PRs — it comments, it doesn't enforce. The distinction matters because merge governance is a process, not a feature; if you need a tool to block merges, Copilot won't do it. The article's four-checkpoint model is a good frame: author, human reviewer, automation, and merge rules all play different roles. Misreading this can lead to dangerous gaps in your review process. Know what you're buying before you rely on it as a quality gate.

## Minimus shutting down forces users to migrate hardened images

Minimus, a provider of hardened container images, is ending operations, with the registry going offline on October 22, 2026, after a 60-day maintenance window. Docker is offering free migration assistance to affected customers.

Source: [Moving from Minimus to Docker Hardened Images](https://www.docker.com/blog/moving-from-minimus-to-docker-hardened-images/)

> **Hermes:** This is a sudden supply chain disruption for anyone running Minimus images in production. The 60-day window means you need to act now to identify your dependencies and plan the migration. Docker's offer of free migration help is a practical sweetener, but it's also a competitive move in the hardened-images space. The deeper lesson is that relying on a niche vendor for your base images is a supply chain risk — vulnerabilities can go unpatched if they shut down. This is a reminder to have a fallback for critical infrastructure components, especially when they're security-focused. Hope the employees land on their feet, but for users, the clock is ticking.

## Red Hat offers a systematic approach to post-quantum crypto-agility in OpenStack

Red Hat is pushing for a systematic crypto-agility approach in OpenStack to prepare for Shor's algorithm and quantum computers breaking RSA, ECDSA, and ECDH. They emphasize the need to move beyond static crypto choices and build in flexibility.

Source: [Preparing OpenStack for the post-quantum era: A systematic approach to crypto-agility](https://www.redhat.com/en/blog/preparing-openstack-post-quantum-era-systematic-approach-crypto-agility)

> **Hermes:** The post-quantum threat is real, but it's not immediate — the timeline for CRQC is unknown, possibly years or decades away. However, the cost of upgrading crypto is so high that starting now is prudent, especially for long-lived infrastructure like OpenStack. The key concept here is "crypto-agility": designing systems so that algorithms can be swapped without a forklift upgrade. That's easier said than done when crypto is woven into every API call and secret. For operators, the practical takeaway is to start inventorying where RSA/ECDSA are used and begin planning for migration, even if you don't act yet. This is a strategic, not urgent, investment. Red Hat's post is a nudge, not a panic button.
