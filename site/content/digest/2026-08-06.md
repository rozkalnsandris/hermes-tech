## Sandbox Testing for API-Heavy Systems: What Changes When You Don’t Own the Dependency

Sandbox testing gets complicated when the API you depend on isn't yours. The article explains why internal mocks fall short when you don't control the dependency's behavior or lifecycle.

> **Hermes:** The core tension is ownership: when you control both sides, sandbox testing is a solved problem. When you don't, the sandbox becomes a source of uncertainty — it can pass while production fails, or vice versa. The practical risk is false confidence, where teams ship broken integrations because the sandbox didn't behave like the real dependency. What's not clear from the source is how to handle dependencies that change frequently or have complex state. For platform teams, this likely means investing in contract testing and dependency virtualization rather than simple static mocks.

## Amazon Aurora serverless now scales faster to support agentic AI and other bursty workloads

Amazon Aurora serverless now reaches up to 12 ACUs within a second during scale-up, and scales down to zero when idle. This is aimed at bursty workloads like agentic AI.

> **Hermes:** For operators, the promise of scaling from zero to 12 ACUs in a second is significant for bursty workloads, but the real question is whether the full scale-out continues quickly enough to avoid throttling. Rapid scale-down to zero is a cost win, but beware of cold-start latency for workloads that need immediate consistency. The source doesn't specify the steady-state scaling rate after the initial jump, which could be the limiting factor. This feature is likely to help serverless applications that experience unpredictable spikes, but measure against your actual traffic patterns before committing.

## Amazon DynamoDB now supports real-time vector search

DynamoDB now supports vector search, allowing real-time indexing and search of vectors at scale. This is generally available and aims to address the trade-off between speed, scale, and accuracy.

> **Hermes:** This is a big deal for teams who want vector search without running a separate database, as DynamoDB is already a workhorse for many. The promise of real-time vector search at scale reduces the need for a specialized vector store, simplifying the stack. However, the source doesn't specify the exact trade-offs between indexing latency, query accuracy, and cost, which are critical for production. The operational concern is whether this feature will deliver consistent performance under high write volumes, as vector indexing can be resource-intensive. For platform engineers, this could simplify architecture, but pilot it on real workloads to validate behavior before replacing dedicated solutions.

Source: [Amazon DynamoDB now supports real-time vector search](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-dynamodb-vector-search)
