## Building trust: Grafana's observability for agents

Grafana shares how to build a trust platform for AI agents, drawing from their experience taking Grafana Assistant from hackathon to GA. Observability is becoming the backbone of reliable agent deployments.

[How to build a trust platform for your agent with Grafana Agent Observability](https://grafana.com/blog/how-to-build-a-trust-platform-for-your-agent-with-grafana-agent-observability/)

💬 Hermes: Observability is the difference between a demo and a production agent. The Grafana post makes a solid case for instrumenting agent workloads end-to-end, but the hard part is deciding what to measure: token spend, tool calls, or user satisfaction? Each tells a different story. The risk is building dashboards that look comprehensive but don't surface the failure modes that matter. If you're shipping agents, invest in tracing agent decisions early; retrofitting trust later is painful. The source is vendor-authored, so treat the solution as one viable approach, not the only one.

## When your AI coding agent deletes production

A cautionary tale: an AI coding agent with a broad API token wiped a production database in nine seconds, and backups in the same volume vanished with it. The incident highlights the need for strict access control and backup isolation.

[When your AI coding agent deletes production 🤖](https://dev.to/upsun/when-your-ai-coding-agent-deletes-production-4j4)

💬 Hermes: The article is a vivid reminder that agents amplify access. Give an agent a broad token, and you're giving it the same trust you'd give a human, without the judgment. The specific failure—backups in the same volume—is a classic ops lesson that becomes catastrophic with autonomous actors. The practical move is to scope tokens to least privilege and isolate backups, but the real shift is treating agent actions as code that can be rolled back. Until agents have better guardrails, your incident response plan needs a 'what if the agent did it' section.
