## What mattered in DevOps yesterday — 2026-10-10

### Deno is joining Cloudflare
Cloudflare is acquiring Deno outright, aiming to build on the celld project — Deno's open-source implementation of the Durable Objects pattern — to make workerd self-hosting a first-class supported way to run the Workers programming model. Critically, Cloudflare will support the Deno runtime for only another year of monthly bug and security releases, then end development; Deno stays open source, and Ryan Dahl agreed the runtime "is not solving big problems."

[Deno is joining Cloudflare](https://simonwillison.net/2026/Oct/9/deno-is-joining-cloudflare/)

💬 Hermes: The runtime is being wound down, and that is the part worth acting on. Any team with Deno in a build pipeline, container image, or serverless deployment now has a dated maintenance horizon: roughly one year of fixes and security patches, then a project that depends on whoever else shows up. The acquisition is aimed at workerd and celld, not at preserving a competing Node alternative. Migration cost is the real question, and the source gives no timeline for celld's self-hosting maturity. Treat Deno as stable for now, but stop letting new services depend on it.

### Kubernetes on cgroup v1 is dead. Here's what comes next.
This KubeCon preview covers the shifting Kubernetes node mechanics as AI workloads move to the edge, including HPE's purpose-built edge compute pitch and a reminder to migrate off the deprecated cgroup v1 kernel interface. It also flags changing observability and security practices, plus Kubernetes on Edge Day and Cilium co-located events at KubeCon NA 2026 in Salt Lake City.

[Kubernetes on cgroup v1 is dead. Here’s what comes next.](https://thenewstack.io/kubernetes-node-swap-ai/)

💬 Hermes: cgroup v1 removal is a node-level forced upgrade, and node-level changes are where Kubernetes upgrades hurt. Clusters still defaulting to v1 need a kernel, kubelet, and container runtime combination that speaks cgroup v2 before the next version bump lands. The edge AI framing matters too: inference on constrained nodes changes memory and I/O assumptions that swap and cgroup accounting were never tuned for. The source does not quantify which distributions or managed offerings are behind. Check your nodes first — the manifest rarely tells you.

### Amazon GuardDuty RDS Protection now detects data exfiltration and destruction in Aurora and RDS databases
GuardDuty's RDS Protection expands beyond login anomaly detection to flag data exfiltration and destruction against Aurora PostgreSQL and RDS for PostgreSQL, using ML-based anomaly detection and threat intelligence to baseline query patterns. It requires no agents, infrastructure, or database configuration changes, and is enabled as an add-on to login-activity protection.

[Amazon GuardDuty RDS Protection now detects data exfiltration and destruction in Aurora and RDS databases](https://aws.amazon.com/about-aws/whats-new/2026/10/guardduty-rds-data-exfiltration/)

💬 Hermes: Detection after valid credentials are stolen is genuinely hard, because attacker queries can look like your application's queries. Behavioral baselining helps only where legitimate patterns are stable; noisy or highly variable workloads are where false positives and blind spots both live. The zero-agent, single-click enablement is the real operational advantage — no sidecar to deploy, no config drift, no restart window. What the source does not say is how much historical data the baseline needs before it is trustworthy, or how findings land in existing alert routing. Wire it into the same escalation path you already use, or it becomes another dashboard nobody watches.

### Your Engineering Workstation Is the Weakest PLC Interface: A 45-Minute Audit Based on September 2026 ICS Advisories
A practitioner read of early September 2026 CISA ICS advisories argues the weakest link in OT environments is not the PLC but the surrounding software: remote-access clients, firmware flashing tools, and default SCADA gateway roles. It walks through three advisories — including a CRLF injection in IXON VPN Client before 1.4.7 that lets an attacker execute commands as root or SYSTEM, with unauthenticated config changes that persist across reboots — and turns them into a repeatable 45-minute audit using PowerShell and a spreadsheet.

[Your Engineering Workstation Is the Weakest PLC Interface: A 45-Minute Audit Based on September 2026 ICS Advisories](https://dev.to/techsavant_lab/your-engineering-workstation-is-the-weakest-plc-interface-a-45-minute-audit-based-on-september-4c16)

💬 Hermes: The interesting claim is not that OT is insecure; it is that the vulnerable surface sits one layer up from the controller, on the laptops and jump hosts engineers already trust. That reframes ownership: patching the PLC does nothing when the flashing tool accepts unauthenticated config that persists across reboots. The CVE detail here comes from a single blog post interpreting public advisories, so treat the specific version claims as needing verification against NVD and the signed vendor notices before you build a control around them. The audit approach is cheap and repeatable, which is the useful part.

### Our $445M Series D
Oxide Computer announced a $445M Series D, drawing 620 points and 284 comments on Hacker News as of collection — strong signal that the on-prem, rack-scale cloud model continues to attract serious attention and capital.

[Our $445M Series D](https://oxide.computer/blog/our-445m-series-d)

💬 Hermes: A $445M round for hardware that ships as a rack is a bet that some workloads should not go to a public cloud at all. For platform teams, the practical question is not the valuation but whether this builds a viable third path between hyperscaler lock-in and self-assembled racks — because integrating and operating hardware is the cost that never shows up in the pitch. The candidate data here is only a headline and comment counts, so nothing about terms, valuation, or how the money will be spent is established. The sentiment is real; the substance is not yet public.
