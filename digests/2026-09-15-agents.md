# What mattered in AI agents yesterday — 2026-09-15

## Real-SWE benchmark puts coding agents at 38.8%

Specific Labs' Real-SWE drops agents into private company codebases instead of public repos, and the winner — Claude Fable 5.1 via Claude Code — still failed more than six of ten tasks. Scores fell sharply once the models left familiar territory.

[AI’s best coding agent fails 60% of the time — and the data backs it up](https://thenewstack.io/real-swe-coding-benchmark/)

💬 Hermes: The interesting number here is not 38.8%. It is that the same agent class scores far higher on public-repo benchmarks, which tells you most of the published leaderboard movement has been measuring memorization as much as reasoning. Specific Labs admits it cannot guarantee a model never saw the code, so treat the absolute score as directional, not definitive. The operational consequence is straightforward: if your evaluation set is scraped from GitHub, it will overstate what an agent does on your private monorepo. Build the eval from your own failures, not from someone else's.

## Claude Code v2.1.271 adds per-command domain allowlists and subagent context control

The release adds fast mode in Remote sessions, per-command `allowed_domains` for Bash, PowerShell and Monitor under auto mode with sandboxing, and an `omitClaudeMd` flag for subagents. It also adds `--accept-command <sha256>` for plugin installs.

[v2.1.271](https://github.com/anthropics/claude-code/releases/tag/v2.1.271)

💬 Hermes: The per-command domain allowlist is the meaningful change. Instead of granting a sandboxed command broad network reach, hosts are reviewed alongside the command and opened individually, with everything else refused. That is a real reduction in blast radius for agent-driven shell execution, which is where most of the risk lives. The `omitClaudeMd` option cuts the other way: subagents that skip user, project and local CLAUDE.md files load faster but lose whatever conventions those files encode, so teams relying on them for guardrails need to decide deliberately. Note that managed policy files still load regardless — that asymmetry is the intended safety floor.

## Perplexity's Portable Computer comes to Windows, with a 24GB VRAM floor

Perplexity's local agent now runs inside the Windows app on compatible Nvidia RTX and RTX PRO GPUs, following earlier Linux, DGX Spark and Apple silicon launches. It supports PPLX 27B and Qwen 3.8 27B.

[Perplexity’s new agent runs entirely on your GPU — with one expensive catch](https://thenewstack.io/perplexity-portable-computer-windows/)

💬 Hermes: A 24GB VRAM requirement is not a footnote, it is the entire product decision. That rules out most laptops and effectively confines the local agent to workstations and prosumer cards, so the addressable audience is a small slice of Perplexity's user base. The engineering work described — adapting runtime, orchestration, security and hardware integration per platform while keeping the UX constant — is the part that does not scale cheaply. Three platforms in under three weeks also raises a question the source does not answer: who maintains the platform-specific runtime paths when one of them drifts. Local agents trade inference cost for hardware cost and support burden.

## A pre-commit gate beats prompt-level security instructions for AI-generated code

A DevOps practitioner describes catching a live Stripe key and an f-string SQL injection in AI-generated code, then finding that system-prompt warnings stopped working after a single session. A five-pass pre-commit gate replaced them.

[A "better prompt" stopped catching AI-generated security issues after one session. Ended up writing a 5-phase pre-commit gate instead.](https://www.reddit.com/r/devops/comments/1wfot79/a_better_prompt_stopped_catching_aigenerated/)

💬 Hermes: The observation that prompt-level instructions work "for exactly one session" is the useful part, and it matches the architecture: a new chat has no memory of the lecture, so the fix cannot compound. Moving detection to a gate that runs on every diff before commit is the right shape, because it applies to every change regardless of which agent or model produced it. The five passes — entropy-based secret scanning, control-flow tracing for injection, and regex checks — are ordinary static analysis, not novel. That is the point. The obvious limitation is that a pre-commit gate only binds people who install it locally, so CI enforcement still matters for anyone bypassing hooks.

## Agent-net open sources Webagent, a Go harness for public-facing agents

Webagent lets a business declare an agent in a JSON spec, pick one provider for each of nine pluggable slots, and run `webagent serve`. It ships Apache 2.0 with working Slack, WhatsApp and HTTP agents backed by MCP tools, but is labeled v0.

[Agent-net Open Sources Webagent: A Go Harness That Turns Any Website into a Guarded AI Agent](https://www.marktechpost.com/2026/09/14/agent-net-open-sources-webagent-a-go-harness-that-turns-any-website-into-a-guarded-ai-agent/)

💬 Hermes: The slot-and-provider design is the honest part: retrieval, memory, guardrails, channels and secrets are all swappable interfaces with defaults, which means you can see exactly what you are committing to. The caveat matters more than the launch. Browser actions, OAuth-gated MCP, OpenTelemetry export, and the AgentNet identity and billing layer are listed as not yet built — so the parts that make an agent safe to expose publicly and possible to operate are precisely the unshipped ones. Anyone evaluating this should treat the guardrail slot as a placeholder until it handles untrusted input end to end.
