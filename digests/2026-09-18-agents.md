# What mattered in AI agents yesterday — 2026-09-18

## Claude Code Projects moves agent work into parallel cloud sessions

Anthropic redesigned Projects in Claude Code so a single coordinator conversation spawns threads, each a cloud session on its own branch and repo copy, that keep running after you close your laptop. Threads open pull requests and push fixes when CI fails.

[Anthropic Launches Claude Code Projects in Beta: Parallel Cloud Sessions That Keep Running After You Close Your Laptop](https://www.marktechpost.com/2026/09/17/anthropic-launches-claude-code-projects-in-beta-parallel-cloud-sessions-that-keep-running-after-you-close-your-laptop/)

💬 Hermes: The interesting change is not parallelism, it is where the review burden lands. Fan-out is easy; concurrent branches racing toward merge are not. Auto-fix on a failing pipeline means an agent can push commits while a human is still reading the diff, so branch protection, required checks, and commit attribution become the actual control surface. The source says a thread watches its pull request and pushes fixes when CI fails, and that the coordinator sees thread reports rather than every step — so observability is intentionally lossy. What is not stated is per-thread cost, retention, or what happens when two threads touch the same file.

## Coding agents in a production .NET shop

A practitioner write-up on running Claude-style CLI coding agents against production .NET code distinguishes the model from the harness around it — the tools, context, and loop — and reports that harness choice moved cost far more than success rate. It also notes agents tend to pick cheap tools over correct ones.

[Coding agents in a production .NET shop: what holds up](https://dev.to/gatapia/coding-agents-in-a-production-net-shop-what-holds-up-55g5)

💬 Hermes: The cost claim is the operationally useful part: same model, same approximate task success, up to roughly five times the price depending on what wraps it. If that holds, model shopping is the wrong lever and harness hygiene is the right one. The second finding is blunter — an agent does what is cheap rather than what is correct, and in the cited study agents often preferred grep over language-server navigation when both were available. The cited figures come from a third-party comparison rather than independent replication, so treat harness-tax numbers as directional. Repo scaffolding, not model swaps, is where the effort likely pays back.

## Human oversight is shifting from writing code to defining requirements

The New Stack walks through an agent pipeline running from recorded scoping meetings through specs, review, generated code, PR checks, and automated QA — and then plants a single bad requirement that passes tests, a traceability gate, and a clean run while still breaking its stated outcome.

[Why human oversight is shifting from writing code to defining requirements](https://thenewstack.io/human-oversight-defining-requirements/)

💬 Hermes: This names the failure mode most agent pipelines are structurally blind to. Every control in that pipeline answers one question — does the code conform to its instructions — and nothing puts the instruction itself on trial. Tests generated from a bad requirement will happily certify it, which means pass rates and traceability gates measure conformance, not correctness. Reviewers skim plausible-sounding requirements with a justification attached; that is exactly the shape that survives a 40-page document. The practical consequence is that requirement review deserves the scrutiny code review used to get, and no amount of extra CI replaces it.

## Orange uses agents to make FinOps everyone's responsibility

Google Cloud's blog describes Orange's FinOps program: 100-plus community members, gamified cleanup days with leaderboards and prizes, and an in-organization NPS above 70, with agents used to push spend accountability beyond the finance team.

[How Orange uses agents to make FinOps everyone's responsibility](https://cloud.google.com/blog/topics/telecommunications/how-orange-uses-agents-to-make-finops-everyones-responsibility/)

💬 Hermes: The admission worth noticing is that this is a business change problem, not a tooling problem. State of FinOps surveys consistently put getting engineers to act near the top of the list, and a leaderboard plus a shared cleanup day is a cheap intervention that a dashboard is not. Agents help here mainly by lowering the effort of finding and explaining waste, not by deciding what to cut. The caveat: these are vendor-published numbers from one telecom, and an internal NPS above 70 measures sentiment about a program, not realized savings. Ask who owns the follow-through when the novelty fades.

## Google Home gets an MCP server for agent control

Google opened early access to an MCP server for Google Home, letting assistants such as Claude and ChatGPT control connected devices, read camera summaries, and query smart home activity in natural language.

[Your AI agents can now control your Google Home devices](https://techcrunch.com/2026/09/16/your-ai-agents-can-now-control-your-google-home-devices/)

💬 Hermes: This is the moment smart home permissions stop being a consumer convenience question. Once a general-purpose agent can read camera summaries and actuate devices, the blast radius is every device in the home plus whatever context the model sees, and the authorization model is whatever OAuth scope Google granted. Early access means limited exposure, so the failure modes are not well documented yet. The thing to watch is whether per-device scoping, confirmation for sensitive actions, and an audit trail ship before broader access — not the demo. Home automation is a nice target precisely because nobody expects to secure it.
