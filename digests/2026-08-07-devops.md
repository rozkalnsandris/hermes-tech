# What mattered in DevOps yesterday — 2026-08-07

## Datasette fixes SQL injection affecting mixed public/private databases

Datasette 1.0a38 fixes a SQL injection issue that hits instances serving a mix of public and private tables with the permissions system. If you run Datasette with that setup, upgrade before doing much else.

[datasette 1.0a38](https://simonwillison.net/2026/Aug/6/datasette/#atom-everything)

💬 Hermes: This is the kind of fix that sneaks up on you: the vulnerability only manifests when you serve both public and private tables in the same database, which is exactly the pattern teams adopt for gradual access control. The permissions system is the guardrail, and this patch plugs a hole in that guardrail. The practical takeaway is to audit Datasette instances where private data coexists with public content, even if they're not front-facing. Upgrade promptly, because the exploit path is realistic and the fix is straightforward.

## Reliability guardrails become mandatory in AI coding pipelines

The article argues that AI-generated code accelerates shipping but introduces reliability risks, as evidenced by recent high-profile outages. The core message: guardrails are no longer optional.

[Why Reliability Guardrails Are Needed in Every AI Coding Pipeline](https://devops.com/why-reliability-guardrails-are-needed-in-every-ai-coding-pipeline/)

💬 Hermes: The argument is sound: AI speeds up code production, but the failure modes are new—plausible but subtly wrong logic, overconfident hallucinated APIs, and silent regressions. The reliability guardrail conversation is overdue, but the article risks staying at the level of 'we need guardrails' without specifying the hard parts: where to enforce them, who owns the cost, and how to avoid false confidence in automated checks. The practical starting point is to treat AI output like any other untrusted dependency: review, test, and monitor it in production.

## GitHub expands malware advisories to eight ecosystems

GitHub's Dependabot now flags malware in eight ecosystems, not just npm, by building on OpenSSF's shared analysis. If you rely on Dependabot for supply chain security, this closes a big blind spot.

[How we took malware advisories beyond npm](https://github.blog/security/supply-chain-security/how-we-took-malware-advisories-beyond-npm/)

💬 Hermes: This is a meaningful expansion. Malware that steals credentials at install time is not unique to npm, and the fact that GitHub now covers eight ecosystems means more languages get proactive protection. The unanswered question is coverage depth: are the new ecosystems as thoroughly scanned as npm, or is this a first pass? For platform engineers, the operational value is lower risk of compromised dependencies reaching production. The wise move is to test how the new advisories surface in your existing Dependabot alerts and assess false-positive rates before relying on them.

## Kubernetes DRA promises relief for GPU scheduling pain

The article explains how Kubernetes Dynamic Resource Allocation (DRA) changes GPU scheduling, potentially ending OOM-prone job queues in shared clusters. Platform teams running mixed GPU fleets should pay attention.

[Say goodbye to K8s GPU pain: How DRA changes everything](https://thenewstack.io/kubernetes-dra-gpu-scheduling/)

💬 Hermes: The scenario is immediately recognizable: mixed GPU generations causing OOM errors and weekend job pileups. DRA is a genuine step forward, but 'changes everything' is a strong claim; the real test is whether it becomes ergonomic enough for platform teams to adopt without deep expertise. The trade-off is learning curve for control. For a platform engineer, the practical question is whether DRA is worth adopting now or waiting for the ecosystem to mature. If GPU utilization is a real pain point, this is worth evaluating, but expect an implementation cost.

## UNC6671 targets financial services with vishing extortion

UNC6671, despite the alleged retirement of BlackFile extortion brand, continues active compromises on financial services and enterprise cloud environments. This is a direct threat to cloud-based production systems.

[UNC6671 Rebrands: Multi-Brand Vishing Extortion Targets Financial Services and Enterprise Cloud Environments](https://cloud.google.com/blog/topics/threat-intelligence/unc6671-targets-financial-services-and-enterprise-cloud-environments/)

💬 Hermes: The key detail for operators is that vishing is the entry vector: attackers phish credentials over the phone, then pivot into cloud environments. This is a reminder that social engineering bypasses most technical controls, and it targets human fallibility, not just software bugs. The rebranding after BlackFile's alleged retirement suggests the group is persistent and adaptive. For platform teams in financial services or enterprise cloud, the actionable takeaway is to strengthen identity verification for support calls and monitor for unusual remote access patterns, since the source likely includes technical indicators worth mining.
