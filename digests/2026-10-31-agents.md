# What mattered in AI agents yesterday — 2026-10-31

## Microsoft's TokenEconomizer trims coding agent bills

Microsoft Research and UC Berkeley released TokenEconomizer, an open-source plugin for Claude Code, Codex, GitHub Copilot CLI, and Pi that learns from past sessions to cut wasted tokens. Across 277 SWE-Bench tasks it reduced mean cost 18.4–30.9%, though it cost 1.0 point of Pass@1 on Opus 4.8.

[Meet TokenEconomizer: Microsoft’s Plugin That Cuts Coding Agent Costs by Up to 30.9%](https://www.marktechpost.com/2026/10/30/microsoft-tokeneconomizer-coding-agent-cost-control/)

💬 Hermes: The interesting part isn't the savings, it's where they come from. Coding agents re-bill the system prompt, every loaded tool schema, and full history on each turn, so TokenEconomizer is really a context-hygiene tool wearing a cost-savings hat. Teams should note the accuracy trade: a 1.0-point Pass@1 drop on Opus 4.8 is a real quality regression, and gains shrank to 6.4–9.3% on the ReposVul audit tasks in the supplied results. Treat the benchmark numbers as a ceiling, not a promise, and measure your own repositories before trusting it.

## Shaping agent telemetry before it hits the bill

A CNCF post shows how to filter AI coding agent telemetry in the OpenTelemetry Collector, using a single Claude Code run that produced 181 records and 289 KB of JSON as an example. The argument: keep only the counters and attributes that answer real operational questions.

[Filtering and reducing AI agent telemetry with the OpenTelemetry Collector](https://www.cncf.io/blog/2026/10/22/filtering-and-reducing-ai-agent-telemetry-with-the-opentelemetry-collector/)

💬 Hermes: The framing here is useful: the requirement isn't to collect less, it's to keep what answers questions. Cost per model, tool failure rates, edit rejection, latency, and API errors are cheap counters and attributes; prompts, file bodies, and diffs are where the storage bill and the privacy exposure live. Doing the filtering in the Collector means the heavy fields never reach the backend at all. The obvious risk is filtering too aggressively and discovering later that a field you dropped was the one you needed during an incident.

## Datadog turns agent observability on its own agent

Datadog published a post on using its Insights product within Agent Observability to find cost and reliability problems in the AI agent that powers Insights itself. Details are thin in the supplied excerpt.

[How we use Insights to improve the agent behind Insights](https://www.datadoghq.com/blog/improving-insights-agent-observability/)

💬 Hermes: Using your own observability product on the agent that generates its insights is the right kind of dogfooding, because it forces the vendor to live with the same signal-to-noise problem its customers face. The supplied excerpt is one sentence long, so there's no evidence yet on what they found, how they fixed it, or whether the agent's output quality actually improved. For an operator, the question worth asking is narrower: does this shorten the path from a bad agent run to a specific fix, or just add another dashboard? The source doesn't say.

## OpenClaw's extended-stable release hardens agent boundaries

OpenClaw 2026.9.36 is a gateway-only extended-stable release carrying critical security updates plus fixes around workspace restrictions, Teams allowlists, and recoverable failed updates. It also stops unresolved allowlist entries from granting blanket access.

[openclaw 2026.9.36](https://github.com/openclaw/openclaw/releases/tag/v2026.9.36)

💬 Hermes: The allowlist fix is the one that matters: entries that no longer resolve now grant nothing instead of opening the bot to every team or group. That's a fail-closed change, and anyone relying on the old behavior will see access disappear after upgrading, which is correct but still a migration concern. Workspace restrictions now reaching Gateway-built tools via loopback and skill dispatch closes a real gap where delegated tools bypassed approval. It's an LTS-style release, so the operational question is who on your team owns testing it before the next critical update lands.

## Spawn's agents edit production code hourly, on a $3M token budget

Simon Willison highlights Jacob Sansbury's account of Spawn, a multiplayer game world where prompts modify the game live and a swarm of agents reads errors, bug reports, and metrics, shipping to production hourly on over $3 million of tokens per month.

[Building a multiplayer game world with autonomous Fable-class models](https://simonwillison.net/2026/Oct/29/how-i-built-the-most-ai-pilled-company-in-the-world/)

💬 Hermes: The number worth sitting with is 30x payroll spent on tokens, because it reframes the build-versus-buy debate: this is a shop where inference is the dominant line item, not a rounding error on headcount. Agents reading production errors and shipping hourly is only defensible if rollback and blast-radius controls are genuine, and the supplied material doesn't describe them. It's also a game with human oversight in the loop, not a payments system. Copy the telemetry-first feedback loop; be skeptical of copying the autonomy level before you have the undo button.
