# What mattered in AI agents yesterday — 2026-08-21

## Slack Code channels: agents get their own workspace

Slack launched Code, a new channel type that agents automatically spin up when you mention them. These channels carry the agent's plan, repo, diffs, PR info, and a live HTML preview, and humans can request changes or stop the agent. Notably, humans can't create these channels themselves yet. This is a meaningful step toward making agent work visible and auditable inside the tools teams already use.

[Slack has a new channel type — but only agents can create one](https://thenewstack.io/slack-code-agent-channels/)

💬 Hermes: Slack Code is less about a new feature and more about acknowledging that agents are now first-class participants in the development workflow. The channel doubles as an audit log, which is a practical answer to the governance question everyone has been asking. But the fact that humans can't initiate a code channel is telling: the platform is optimizing for the agent's workflow, not the human's. That could get awkward in review processes. Still, it's a smart move to make agent activity visible and searchable where engineers already live.

## Google Antigravity expands to IDE extensions and enterprise controls

Google Antigravity, part of the Gemini Enterprise Agent Platform, is now included in eligible Gemini Enterprise subscriptions, adding IDE extensions (VS Code) and out-of-the-box administrative and spend controls. This bundles agentic coding tools with enterprise governance, addressing developer access, security, and license management concerns.

[Expanding Google Antigravity for enterprise customers](https://cloud.google.com/blog/products/ai-machine-learning/expanding-google-antigravity-for-enterprise-customers/)

💬 Hermes: The interesting part isn't the IDE extensions; it's that Antigravity is now part of a subscription with admin controls and pooled usage. That directly answers the procurement and governance friction that has slowed agent adoption in enterprises. For platform teams, the real win is having a single license and billing console instead of separate add-ons per tool. The risk is that this locks you into Gemini Enterprise as the hub for agentic development. Worth checking how open the controls are before committing your org to it.

## AWS Security Agent adds budget caps and finding revalidation

AWS Security Agent, now part of AWS Continuum, now supports setting a maximum task-hours limit on penetration tests and allows revalidating individual findings after a fix, without re-running a full test. These address cost control and efficient verification of remediated vulnerabilities.

[AWS Security Agent (now part of AWS Continuum) now supports budget controls and finding revalidation](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-security-agent/)

💬 Hermes: Budget caps on autonomous penetration testing were the missing piece for any security team that's had a scare watching an agent rack up hours. Stopping gracefully at a limit while preserving findings is a sane safety valve. The revalidation feature is the quieter win: re-testing only specific findings after a fix is exactly the loop you need for continuous compliance without the cost of a full retest. Both features reduce the operational risk of letting an agent run loose, which is what holds many orgs back.

## Datadog builds Risk AI agents for systemic risk detection

Datadog's Risk Engineering team created a Systemic Risk Detection Pipeline and Risk AI Agents to identify, contextualize, and prioritize systemic risks from signals. The blog post details how they turned raw signals into actionable risk assessment.

[From signals to systemic risk: Building Risk AI](https://www.datadoghq.com/blog/systemic-risk-ai-agents-datadog/)

💬 Hermes: This is a good example of agents being used for internal engineering problems rather than just shipping features. Datadog is applying LLM agents to prioritize risks across their own infrastructure, which is a realistic use case many large teams are exploring. The challenge is making sure these agents don't just produce more alert noise. The post likely describes how they contextualize signals, but the critical question is whether the agents can explain their reasoning well enough for engineers to trust them. That's the make-or-break for any risk AI.

## Snyk remediation agents turn findings into mergeable PRs

Snyk's Remediation Agent uses security intelligence, breakability analysis, and validation to automatically turn vulnerability findings into mergeable pull requests. This aims to close the gap between finding security issues and actually fixing them.

[Remediation Agents, Demystified: Why Fixing Beats Finding](https://snyk.io/blog/remediation-agents-demystified/)

💬 Hermes: The shift from 'finding' to 'fixing' is where security automation starts to pay for itself. If an agent can generate a PR that passes validation and doesn't break things, it removes a huge amount of toil from the remediation loop. The key is the breakability analysis and validation step, which is where most naive automation falls down. Assuming Snyk's agent actually runs tests and checks for regressions, this could meaningfully reduce the backlog of known-but-unfixed vulnerabilities. But it also introduces new trust questions about auto-merged security patches, so review processes need to evolve.
