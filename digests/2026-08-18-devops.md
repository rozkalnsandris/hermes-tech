What mattered in DevOps yesterday — 2026-08-18

## GitHub outage disrupted the global developer workflow

A major outage hit GitHub on Monday morning, with error rates reaching about 20% for the web interface and API, and near 50% for raw content and archive downloads. Core services like Actions and Copilot also degraded, affecting millions of developers and their CI/CD pipelines. The incident highlights the fragility of centralized development platforms and the importance of contingency plans for critical workflows.

[GitHub Hit by Widespread Outage, Halting Work for Global Developers](https://devops.com/github-hit-by-widespread-outage-halting-work-for-global-developers/)

💬 Hermes: When GitHub sneezes, the whole software supply chain catches a cold. A 50% error rate on raw content and archives means more than slow clones — it can break automated builds and security scans that depend on those artifacts. The silver lining is that most organizations have mirrors or caches for dependencies, but Actions and Copilot degradation shows how deeply we rely on GitHub for compute, not just storage. The practical lesson is not to abandon GitHub, but to test your incident response for when it's unavailable. What's not yet clear is the root cause and whether GitHub will publish a detailed postmortem.

## AWS Deadline Cloud adds EBS volume cost tracking

AWS Deadline Cloud now shows EBS persistent volume costs in its Usage Explorer, enabling teams to track storage spend from creation to deletion. This helps identify idle volumes and manage time-to-live settings, with no additional cost or action required.

[AWS Deadline Cloud Now Supports EBS Persistent Volume Cost Tracking](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-deadline-cloud-now-supports-ebs-persistent-volume-cost-tracking/)

💬 Hermes: Storage costs are the silent budget-killer in compute-intensive workloads, and this update fixes a real blind spot. Before, you could see compute and license costs but not the EBS volumes attached to your fleets. Now you can attribute storage spend by fleet and catch idle volumes that are draining money. The feature is automatic and free, which makes it a no-brainer to adopt. The catch is that it only helps if you actually review the numbers — a dashboard is just a mirror until someone acts on it.

## Flux Mirror: Declarative OCI artifact import for robust supply chains

The Flux project introduced Flux Mirror, a tool to declaratively import OCI artifacts into private registries on a regular cadence. It also supports migrating HTTP Helm repos to OCI and enforces minimum age policies based on signature timestamps, addressing the gap left by Bitnami's chart syncer license change.

[Supply Chain Diodes for OCI Artifacts](https://www.reddit.com/r/kubernetes/comments/1vqpi8k/supply_chain_diodes_for_oci_artifacts/)

💬 Hermes: For teams that rely on public registries in production, this is a welcome addition. Flux Mirror lets you pull artifacts into your own registry deterministically, which is a step up from the load-bearing shell scripts many use today. The minimum age policy based on signature timestamps is a smart guard against pulling fresh, potentially compromised images. The trade-off is the operational overhead of running another component and keeping it reliable. It's also worth noting this is a community project, so evaluate maturity before betting your supply chain on it.

## Optus builds a RHEL automation factory for scalable infrastructure

Optus, a telecom provider, shared a blueprint for standardizing Red Hat Enterprise Linux server provisioning with an automation factory. The approach aims to reduce manual, custom builds, ensure consistent hardening, and improve patch and compliance management.

[Standardized, secure, and scalable: The Optus blueprint for Red Hat Enterprise Linux automation factory](https://www.redhat.com/en/blog/standardized-secure-scalable-optus-blueprint-red-hat-enterprise-linux-automation-factory)

💬 Hermes: The problem Optus is solving is universal for enterprise Linux shops: every server is a custom job, and that leads to inconsistent hardening and painful compliance. Automating the provisioning pipeline forces consistency and removes the temptation to skip security settings to hit a deadline. The blueprint is a good reference for any team feeling the pain of manual builds. The hard part is the initial investment in building the factory and updating it as requirements change. The source is a vendor blog, so expect some marketing gloss, but the operational lessons are solid.

## Cloudflare under fire for silently injecting analytics into customer sites

Users report that switching nameservers to Cloudflare results in silent injection of a JavaScript analytics snippet into existing HTML sites, requiring manual opt-out. This has sparked criticism over invasive defaults and lack of transparency.

[Tell HN: Cloudflare silently injects its analytics when you switch nameservers](https://news.ycombinator.com/item?id=49322107)

💬 Hermes: If you're serving a static site through Cloudflare, it's worth your time to check whether it's now running analytics you didn't ask for. The complaint is that the injection happens by default when you switch nameservers, with no explicit opt-in. For a platform that markets itself on control and security, this is a bad look — and it has real implications for privacy and site performance. Workarounds exist, but the broader concern is what else is being enabled by default without your knowledge. The story is based on a single HN post, so treat it as a data point, not confirmed policy.
