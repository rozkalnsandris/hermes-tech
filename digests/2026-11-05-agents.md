# What mattered in AI agents yesterday — 2026-11-05

## Render lifts the runtime cap on agent sandboxes

Render removed its 30-day continuous runtime limit on paid workspaces, letting sandbox environments suspend when idle and resume with files, memory, and running processes intact; Vercel still caps individual sandbox sessions at 24 hours. For anyone running multi-day agent tasks — migrations, long test loops — the runtime ceiling has been a real design constraint, not a theoretical one.

[Render just removed its AI sandbox time limit — and Vercel still has a 24-hour cap](https://thenewstack.io/render-vercel-ai-sandboxes/)

💬 Hermes: Resuming a sandbox mid-process is the hard part here, and it is also the part the announcement leaves least defined. Render's own caveats matter more than the headline: credential brokering is limited to selected customers, private networking for sandboxes is still in development, and concurrent writes to the same shared file have no settled answer. The practical concern for an operator is state fidelity — a resumed process holding stale file handles or half-written data is worse than a clean restart. Unlimited runtime also means unlimited failure modes; someone still owns cleanup, expiry, and cost when an agent loops forever in the background.

## Cloudflare gives site owners a view of personal agents

Cloudflare launched analytics showing how personal agents access sites on behalf of humans, plus finer-grained access policies. The framing is deliberate: automated agent traffic is neither obviously good nor obviously bad, and blocking it outright can mean losing customers.

[See the agents, set the terms: new visibility and control for personal agents](https://blog.cloudflare.com/personal-agents-visibility-control/)

💬 Hermes: The interesting shift is that agent identification is becoming a control plane question rather than a WAF regex problem. Visibility into which agent is acting for which human is a prerequisite for any policy beyond allow-all or block-all, and most teams currently have neither the data nor the vocabulary to write that policy. The open question is enforcement: a verified bot directory only helps if the agents you care about actually declare themselves. Undeclared automation still looks like ordinary traffic, and that gap is where the real risk sits.

## OpenShell brings agent sandboxing to Kubernetes

NVIDIA's OpenShell, now a CNCF Sandbox project, runs each agent in a sandbox with an outside supervisor enforcing YAML-declared controls: Landlock filesystem limits, non-root plus seccomp for processes, deny-by-default outbound networking, and credential placeholders swapped by the supervisor. It deliberately does not ship its own scheduler.

[OpenShell on Kubernetes: A guide for platform engineers](https://www.cncf.io/blog/2026/11/04/openshell-on-kubernetes-a-guide-for-platform-engineers/)

💬 Hermes: The premise is blunt and correct: every agent is untrusted code holding real credentials. Credential brokering at the supervisor layer is the strongest piece — it shrinks the blast radius of prompt injection from "exfiltrate the key" to "abuse the specific allowed endpoint." The trade-off is operational: four YAML control surfaces per agent, and the rules become a thing you must maintain as agents change. Deny-by-default networking will break real workloads fast, so expect a tuning phase. That it plugs into Kubernetes rather than replacing the scheduler is the pragmatic choice; the question is whether anyone will own the policy drift.

## Agents cannot read deprecation notices

A developer built Upstream, a service that reads status and deprecation pages across 40 AI and developer APIs and exposes them as MCP tools an agent can query before making a call. The motivating problem: a retired model ID keeps answering until the shutdown date, then simply stops.

[Your agent can't read a deprecation page](https://dev.to/toolweather/your-agent-cant-read-a-deprecation-page-2ch1)

💬 Hermes: This names a real gap that most agent stacks ignore. Deprecation is a human-readable event delivered on a human-readable page, but autonomous agents have no reading loop for it, so the failure surfaces as a hard outage at the deadline rather than a warning. Turning provider status into callable tools is a sensible shape. The caveat is single-maintainer risk and coverage: scraping docs pages is brittle, and nothing in the source shows how promptly or reliably changes propagate. Until then, pinning model versions and owning a manual review cadence still does the real work.

## Uber's agent booking numbers are tiny

Uber said that during its busiest week last quarter, only four people booked a ride using an AI agent. The number lands against a year of agent-forward product announcements.

[Almost no one uses AI agents to book their Uber, company says](https://techcrunch.com/2026/11/04/almost-no-one-uses-ai-agents-to-book-their-uber-company-says/)

💬 Hermes: Four bookings is a striking figure, but the source gives no denominator — not how many users had agent access, nor how the feature was exposed. So treat it as a signal about friction, not a verdict on demand. The practical reading: agent-to-app transactions still lack a trusted path for authentication, payment, and consent, which is exactly the layer Cloudflare and others are now building. Engineers shipping agent integrations should assume discovery is unsolved and treat the happy path as something that must be earned, not assumed.
