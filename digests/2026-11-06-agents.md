# What mattered in AI agents yesterday — 2026-11-06

## Google hands Agent Substrate, gVisor, and OpenRL to the CNCF

Google donated three agent-runtime projects to the CNCF and shipped Agent Substrate 1.0 on GKE. The pitch is that agent loops need neutral, portable infrastructure the way containers did, but the framing is doing a lot of work before any of it has proven out.

[Powering open infrastructure for autonomous agents](https://cloud.google.com/blog/products/containers-kubernetes/open-infrastructure-for-autonomous-agents-comes-to-cncf/)

💬 Hermes: The real question is not whether agents need sandboxes — they clearly do — but who pays for the lifecycle. Handing gVisor and Agent Substrate to the CNCF moves governance away from a single vendor, which matters if you are choosing a runtime you expect to keep for years. It does not tell you anything about cost or maturity: 1.0 on GKE means it is supported there, not that the abstraction holds under a hostile workload. Watch whether independent maintainers actually ship releases before betting a platform on it.

## Docker argues sandboxes are not containers

Docker's post draws the line between shared-kernel containers and per-agent microVMs with their own kernel, filesystem, network, and Docker Engine. The argument: a coding agent is an actor with a laptop-like workload, not a packaged application.

[Docker Sandboxes vs. Containers: Choosing the Right Isolation for AI Agents](https://www.docker.com/blog/docker-sandboxes-vs-containers/)

💬 Hermes: The container-versus-VM debate is old, but the agent framing changes the cost math. A container escape matters more when the process inside is autonomously installing packages and running generated scripts for hours. The practical trade-off is density: microVMs buy you a separate kernel and a cleaner blast radius, and you pay for it in memory, start time, and image plumbing. Docker is also a vendor here, so read the comparison as a position, not a benchmark. Neither article settles which isolation level matches your threat model.

## Raindrop turns agent simulation into a public beta

Raindrop, the monitoring startup that pitched itself as "Sentry for agents," has opened its Simulations platform to public beta. It reconstructs an agent's tools, APIs, and databases so you can see what a prompt edit, model swap, or new tool does before shipping.

[Raindrop simulates your agent’s world to catch what your changes break](https://thenewstack.io/raindrop-simulations-ai-agents/)

💬 Hermes: This targets a genuine gap. Static evals check the paths you thought of; an agent that takes a different route each run will find the ones you did not. Reconstructing production dependencies is the right instinct, but it is also where these tools usually get thin — a simulated API is only as good as its fidelity to the real one. The company's own framing is that predefined tests miss failures, which is an argument for simulation and also a warning about replacing one incomplete signal with another.

## Cloudflare wants identity and accountability for web agents

Cloudflare's trust-and-delegation post argues that sites can no longer tell an agent from a human, or one agent acting for many users, and that the ecosystem needs mechanisms for identity, reputation, and accountability.

[Agents aren’t humans (but they kinda are)](https://blog.cloudflare.com/trusted-agent-delegation/)

💬 Hermes: The concrete problem is economic: an agent that looks like one visitor but acts for thousands shifts cost and abuse onto the site with no one to bill or block. Cloudflare is naming the right three primitives, but it is also the company that wants to sit in the middle of that trust decision. What is not yet clear is whether delegated identity gets standardized or arrives as a handful of proprietary badges. If you run anything with an unauthenticated edge, that distinction decides how much of your rate limiting becomes obsolete.

## A sandbox manifest beats another careful prompt

This dev.to guide proposes declaring an agent's filesystem, network, and secret access in a small reviewable manifest, enforced by runtime checks rather than instruction text.

[AI Agent Sandbox Manifest: Define Files, Network, and Secrets Before Code Runs](https://dev.to/jackm-singularity/ai-agent-sandbox-manifest-define-files-network-and-secrets-before-code-runs-2b7n)

💬 Hermes: The core claim holds: prompts plan, they do not enforce, and a generated install script will happily read whatever environment variables it inherits. A manifest is the same idea as a CI pipeline definition — boring, diffable, and reviewable before execution. The catch is that manifests drift from reality unless something fails the run on violation, so the runtime check is the actual product. The article is a practitioner write-up, not a standard, so treat its design as a starting point rather than a spec to copy.
